# Security policy

## Reporting a vulnerability

Please do not open a public issue for a security problem. Use [private vulnerability reporting](https://github.com/cuaderna/cuaderna/security/advisories/new) on this repository, and describe what you found, how to reproduce it and which version you tested.

## Supported versions

Fixes go into the latest release only. The project is in early development, so older releases are not patched.

## What to expect

A report is read and answered on a best-effort basis by a single maintainer, so there is no response time to promise. A confirmed problem is fixed in a new release and described in a published advisory, crediting the reporter if they wish.

## Scope

[docs/security.md](docs/security.md) says what cuaderna protects and what it does not. A report that depends on something listed there as not protected is a documented limit, not a vulnerability, but is still welcome as an issue.
